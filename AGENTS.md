# AGENTS — netflix-home

## What this is

A local, Netflix-style streaming app. Node/Express backend scans a movie folder (default `G:\NETFLIX`), probes files with ffmpeg/ffprobe, records everything it knows in one SQLite catalog (`catalog.db`), builds cached hero previews, streams video with HTTP range support, and downloads films and episodes from the Castle catalog. Vanilla JS frontend in `public/`.

The shipped artifact is a **single self-contained EXE**: server, UI, ffmpeg and ffprobe are bundled with Node SEA (`bundle/`), so the deployment folder holds only the EXE, the videos and `.cache/`.

## Commands

```powershell
npm install          # deps: express, ffmpeg-static, ffprobe-static, esbuild, postject (dev)
npm start            # dev server, port 3000 (random free port if taken)
npm run dev          # node --watch
npm run bundle       # build dist\netflix-home.exe (esbuild → SEA blob → postject → GUI subsystem)
npm run deploy       # bundle, then copy the EXE to G:\NETFLIX and clean legacy folders
node scripts/bench.mjs  # perf harness: temp library, prints timings/bytes, exits non-zero on regression
```

Run `npm run deploy` after every app change: the copy in `G:\NETFLIX` is what Yassine actually launches, and it must match the source. `deploy.ps1` alone only copies an existing build, so run `npm run bundle` first when you changed `public/` or `server/`.

There is no test suite. Verify by starting the server and hitting the API, then exercising the UI over CDP:

```powershell
Invoke-RestMethod http://localhost:3000/api/library
Invoke-RestMethod http://localhost:3000/api/db/stats
Invoke-WebRequest "http://localhost:3000/api/art/<id>/poster?w=480" -SkipHttpErrorCheck
```

## Layout

- `bundle/build.mjs` — esbuild CJS bundle, SEA blob, postject injection, PE subsystem patch (no console window)
- `bundle/entry.js` — resolves the library root, extracts UI + ffmpeg once to `.cache\app\<buildId>`, single-instance check, opens the browser, writes `launcher.log`
- `bundle/shims/` — `ffmpeg-static` / `ffprobe-static` replacements that read `FFMPEG_PATH` / `FFPROBE_PATH`
- `server/index.js` - Express routes: library, rescan, stream, artwork, item, hero, series catalog, castle download, `GET /api/db/stats`, `POST /api/quit`
- `server/library.js` — folder walk with a saved directory index, filename/NFO parsing, ffprobe metadata, `items` table (payload JSON), instant library load from the DB on boot
- `server/db.js` — **one** SQLite database (`.cache\catalog.db`): schema, WAL pragmas, one-time migration from the old `pictures.db` / `library.db` / `trailers.db`, asset helpers, `dbStats`
- `server/pictures.js` — picks a still per title by edge density over several sampled moments, stores the JPEG in `.cache\pictures\` and the row in `catalog.db`
- `server/hero.js` — hero stills + 8 s preview clips indexed in `catalog.db`, background warm-up that aborts on playback
- `server/artwork.js` - Cinemeta poster/backdrop/logo downloaded once into `assets` BLOBs, served with an ETag; `sizedArt` renders JPEGs at the requested ladder width into `.cache\art\sized\`; `warmArtwork` imports legacy `.cache\art` files
- `server/subs.js` - subtitle sidecars read once into the `subtitles` table, body served from the DB with an ETag
- `server/audio.js` - audio-track probe cached in `audio_probe` / `audio_tracks`, on-demand dub remux into `.cache\audio\`
- `server/downloads.js` - Castle HLS downloads: ffmpeg remux into the library, subtitle/art sidecars, queued jobs with pause/resume/cancel
- `server/torrentio.js` - keyless Torrentio client: lists releases for an IMDb id, ranks 1080p+ by swarm health and size, builds magnets
- `server/torrent.js` - aria2c torrent acquisition (metadata only, then one selected file), ffprobe track selection, container decision (keep the release's own file when the browser plays it, else H.264 remux into MP4), embedded-subtitle extraction to `.vtt`
- `server/trailers.js` - Cinemeta (keyless) resolves the official YouTube trailer; KinoCheck is the second source for titles it misses; last resort is `ytsearch5:"<title> <year> official trailer"`; the cut is downloaded once into `.cache\trailers\`
- `server/settings.js` - persisted `offline` flag and `castleFallback` switch, read by the API and the download/trailer warm-ups
- `server/config.js` - `config.json` beside the app: the library folder chosen in Settings, read before the library is resolved (it cannot live inside the library it points at)
- `server/proc.js` — every ffmpeg/ffprobe/yt-dlp child: below-normal priority, one heavy media job at a time (`mediaLane`), ffprobe lane, playback-aware warm-up gate
- `public/index.html` + `app.js` + `styles.css` — home UI, search, series/detail sheets
- `public/watch.html` + `watch.js` + `watch.css` — custom player
- `public/common.js` — shared formatting, storage, and API helpers
- `<library root>\.cache\` — `catalog.db`, `pictures\`, `hero\`, `audio\`, `art\`, `frames\`, `trailers\`, `app\` (extracted UI), `port`, settings (gitignored)
- `deploy.ps1` — copies the built EXE to `G:\NETFLIX` and removes legacy `server/public/node_modules/package*.json`
- `media/` — fallback library used when no `G:` location exists; test videos can live here (gitignored)
- `G:\NETFLIX\` — real deployment: `Movies\`, `.cache\`, `netflix-home.exe`

## Conventions

- **Fix the app, not the file - and fix it for every title.** A wrong result on disk (an out-of-sync subtitle, a retimed sidecar, a hand-edited row, a deleted episode) is a symptom. Never repair it by hand and stop there: find why the app produced it, change the code so the app produces the right result, and let the app redo the work. The fix must be generic - keyed to a pattern the app can detect (an fps mismatch, a missing track, a bad probe), never to the one title that was reported. A manual patch is undone by the next download, hides the bug, and leaves every other title broken.
- Vanilla ES modules, no framework. The bundler is only for the single-file EXE.
- **Everything metadata-ish lives in `catalog.db`.** One `node:sqlite` connection (`server/db.js`) owns the file, opened with WAL, `synchronous=NORMAL`, `busy_timeout=5000`, a 32 MB page cache and mmap. Small assets (posters, backdrops, logos, subtitle text) are rows in `assets` / `subtitles`; large media (pictures, hero stills/clips, trailers, dub MP4s) stay on disk and are indexed by path. Do not add a second database file for a new feature: add a table to `db.js` and a prepared statement in the owning module.
- Scans write inside one `transaction()`; the HTTP side reads from memory, so a scan never blocks a request.
- **A launch never re-probes the library.** `dirs` stores each folder's listing (name/size/mtime); `walkIndexed` re-lists the folder, reuses saved sizes for names that still exist and stats only new ones. Directory mtimes alone are unreliable on NTFS (lazily updated), so the listing is always read and mtimes are only a hint. A scan that changes nothing keeps `updatedAt`, so the `/api/library` ETag stays stable and browsers get `304`. `fs.watch(libraryRoot, {recursive:true})` triggers the same debounced refresh (2.5 s, `.cache` and `*.part` ignored) instead of a launch crawl. Do not add a second scan path: call `refreshLibrary(reason)` in `index.js`.
- `plan.md` holds the performance roadmap (low-priority ffmpeg, gzip, sized artwork, DOM diffing); keep measurements there and in `progress.md` when a phase lands.
- **Never call `execFile`/`spawn` for ffmpeg, ffprobe or yt-dlp directly.** Use `run()` / `spawnNice()` from `server/proc.js`: they set below-normal priority and admit work through `mediaLane` (one heavy job) or `probeLane` (three probes). Warm-up loops check `playbackActive()` so a build never fights a stream.
- **Warm-ups are optional and gated.** `warmHeroes` / `warmTrailers` / `warmArtwork` start only after the first `/api/library` request (`libraryRequested` + `queueWarm`, deduped by `updatedAt`) and never block a request; a background hero build aborts mid-build when playback starts. Keep new warm-up work behind the same gate.
- **DB housekeeping rides on real scans.** `purgeOrphans()` runs at most every 6 h (30-day age cutoff), `ANALYZE` after a scan that wrote more than 50 rows, `VACUUM` only when idle with ≥25 % free pages and at most once/24 h; `/api/quit` runs `ANALYZE` + `maybeVacuum`. `dbStats()` now also reports `mainBytes`, `walBytes` and a `process` block (cpu, rss, heap, uptime).
- `/api/library`, `/api/art/*` and `/api/subtitle/*` send an ETag and answer `304 Not Modified`, and `getLibrary()` in `public/common.js` uses `cache: 'no-cache'` so every navigation revalidates instead of downloading 20 KB again. `GET /api/db/stats` returns file size and row counts for debugging.
- **Bytes matter: keep the cache rules intact.** `/api/library` is gzipped once per revision (`Vary: Accept-Encoding`, same ETag), and `/api/art/:id/:kind?w=` serves a JPEG from the `sized` folder at the nearest ladder width (160/240/320/480/640/960/1280). HTML and every `public/` code asset (`.js`, `.css`, fonts, icons) are `no-cache`, so a browser revalidates and a deploy reaches an already-open tab; `/x.css` and `/x.js` still carry `?v=<asset stamp>` in the HTML and express answers `304` when nothing changed. Don't request art without a width: cards use 480 (grid 640), episode thumbs 320, hero and media-session art use the original or 1280.
- **A poll that changed nothing must not touch the DOM.** `loadLibrary()` compares `libraryPrint` (length + every mtime) as well as `updatedAt`; identical rows skip `renderAll()`. Rows use `content-visibility: auto` so offscreen rows cost no layout/paint, and the watch page fetches its scrubber sprite only on the first timeline hover.
- **Top nav is Home / Local / Favourite / Online.** `Local` lists the library, `Favourite` lists My List entries (local + Castle snapshots), and `Online` draws 30 random catalog titles from `GET /api/castle/browse` (merged genre searches, cached until **Shuffle** sends `?fresh=1`). archive.org is gone: no `/api/catalog/*` routes, no picker sheet.
- Build user-facing DOM with `textContent` or `createEl`, never interpolate filenames into `innerHTML` (local files can contain arbitrary characters).
- Keep the Netflix look: black/near-black surfaces, `#e50914` red, white play buttons, 16:9 cards.
- Progress and My List live in `localStorage`; don't move them server-side without a reason.
- **One card per title.** `seriesKey` is derived from the show's title only, never from its folder, so the same series under `Downloads\` and `Movies\Downloads\` stays one show: one card, one episode list, and Next episode crosses folders. The home page groups series by normalized title as a second guard, and `group.ids` keeps every file id of a title mapped to its card so search and My List never draw a second card for a duplicate-quality copy. Downloads skip a file whose name already exists anywhere in the library instead of writing a `" (1)"` copy.
- Paths from IDs are resolved and checked against the library root in `resolveItemFile`.
- The library root is resolved once: `LIBRARY_ROOT` → the folder in `config.json` beside the app (the Settings field) → an exact `Movies` folder beside the app → `G:\NETFLIX` → `G:\Movies` → `G:\` → project `media\`. Compare directory names exactly; Windows is case-insensitive but the project also has `media\`. A configured folder that is missing (unplugged drive) logs a warning and falls through to the next candidate instead of failing the launch.
- Series click opens the catalog sheet (`openSeriesSheet`), which merges local episodes into the Castle episode list: local episodes get **Play** plus their progress bar, the rest keep **Download**. Episode thumbnails are the catalog API's images; never generate frames for that sheet. **The list is painted once:** it used to draw the on-disk episodes first and repaint with the Castle merge, so a downloaded episode appeared alone for a frame and then the whole season (the visible flicker). The sheet now leaves the skeleton up and paints after the catalog detail - and after `selectCastleSeason` when the clicked episode sits in another season - so there is one paint. `state.castleListReady` stops `syncCastleSheet` from repainting a skeleton, and `state.castleNote` carries the offline/catalog-failure message plus the hidden bulk buttons across queue repaints. The local-only list still exists; it is what the catch block draws when the catalog is offline or the series is unknown.
- **The player's Episodes panel always lists the whole season.** `loadEpisodes()` in `watch.js` merges `/api/series/:key` (files on disk) with `/api/series/:key/catalog` (every episode the catalogue knows) by season and episode number, and the season picker lists every season either source has. A row with no local file has no id, so it is drawn `.is-missing`: dimmed, disabled, meta line "Not downloaded". Offline or a title outside the catalogue leaves the old local-only list exactly as it was.
- The player's **Next episode** button asks `GET /api/next/:id`. Local result → `/watch.html?id=<next>`; catalog result → `/?open=<current id>&season=<n>&episode=<n>`, which `boot()` turns into the series sheet with that season open and the row highlighted (`.is-target`). In the last 10 s the card opens by itself (`syncNextDue` toggles `.is-due`), but only for a **local** next episode: a catalog-only one cannot play, so it stays a hover card. While it is up `hideUiNow` keeps the control bar visible, and on a phone the popup pins to the viewport (`position: fixed`), because the narrow layout hides hover cards.
- The player has no playback-speed control; the ±10 s jumps are 54 px with 32 px icons.
- **Dubs/audio tracks**: every HLS download maps all audio renditions (`-map 0:v:0 -map 0:a?`), so the original language and the English dub both land in the file. Browsers can only play the first audio stream, so the player fetches another track as `/api/stream/<id>?audio=<streamIndex>`, which remuxes it once (`-c copy`) into `.cache\audio\` and caches by id + mtime + track. The variant keeps the source container (`.mkv` for a copied release) because Chromium plays Matroska and an MP4 would need the HEVC `hvc1` retag; a track that is not already AAC is encoded with `-aac_coder fast`, since copying E-AC3/AC-3 gives a silent file. Chromium exposes no `video.audioTracks` (measured: `hasAudioTracks: false`), so the variant is the only way to switch. The CC panel's Audio section lists `/api/audio/<id>` and hides itself for single-track files; the pick is stored per series under `netflix-home:audio:series:<key>`.
- **Downloads prefer Torrentio, Castle is the fallback.** `POST /api/castle/download` resolves the IMDb id (Cinemeta, cached per Castle id), asks Torrentio for releases, and only queues an HLS job when Torrentio has nothing usable (offline, no id, no H.264 release declaring the original language + English). Castle still owns every piece of metadata: title, logo, rating, artwork, description, seasons. **The audio rule is a hard gate on the evidence, not a preference:** a release that lists its languages must list an English track, and either the title's original language or the `dualAudio` flag (anime rips tag only "en" for a file that really carries jpn + eng; `pickTracks` still rejects such a file after the probe when the original track is missing, and the job moves on). A release that lists neither is never downloaded (`planTorrentRelease` drops it before the queue, and an empty pool answers 409 with "none of the N releases carries the original audio and an English dub" instead of queueing anything). Releases that tag no languages at all are kept, because Torrentio often has none (RARBG packs), and `pickTracks` then rejects the file after the probe when it lacks either track - a non-English file with a single audio track is rejected too, since that is the original without a dub. English subtitles are the third half of the rule: embedded tracks are extracted, and a missing English track is fetched from OpenSubtitles after the episode is installed; a failed fetch is logged, not hidden. The torrent job downloads one file into `.cache\torrent\<jobId>`, probes it, keeps the original + English audio (English required), copies H.264 video, re-encodes any other codec with the first candidate that survives a 10-bit HEVC test clip (`h264_nvenc` preset `p1 -cq 23` fed by NVDEC through `scale_cuda=format=nv12`, then `h264_qsv` on the QSV decoder, `h264_amf`, else `libx264`; `VIDEO_ENCODER=<name>` forces one, and a hardware failure retries once on libx264), keeps an AAC track as it is and re-encodes the rest to AAC, writes every embedded text subtitle as `<name>.<lang>.vtt` in one ffmpeg pass, and only then moves the MP4 into the library. The output name's quality comes from the probed width as well as the height, so a 1920x960 master is labelled 1080p, not 720p. A release that turns out to lack English audio is discarded and the next candidate is tried; `GET /api/releases?imdbId=&season=&episode=` shows the ranking. `GET /api/castle/plan?movieId=&season=&episodes=` answers the same ranking per episode (10 min cache, 4-way concurrency) so the sheet can print the real quality and size before the click; the labels and the job share `planTorrentRelease()`, so they cannot drift. `bin\aria2c.exe` is bundled and exposed as `ARIA2C_PATH`. `bin\` is not tracked (global gitignore), so `bin\aria2c.exe` has to exist locally next to `bin\yt-dlp.exe` before `npm run bundle`.
- **The Torrentio switch is `castleFallback`** (Settings sheet, default on). On, a Torrentio miss falls back to Castle's HLS stream; off, the request fails with 409 `no Torrentio release with English audio and Castle fallback is off` instead of silently using the 720p Castle stream. The plan sheet labels the source per episode, so the two paths never disagree with the click.
- **An IMDb id is resolved against the show's run, not its first year.** Castle files a long-running series under its last season (it says "Suits" is 2019), while Cinemeta's search only knows first years, so `pickImdbId()` in `server/imdb.js` asks `getTitleRun()` (Cinemeta `releaseInfo`, 6 h cache) for every exact-title candidate and keeps the one whose run covers the requested year; the closest first year is only the fallback, and a fuzzy match (no exact title) keeps that old order. Without it, Suits resolved to the 2018 Korean remake, whose only release declares Korean audio, so the series sheet looked empty and fell back to Castle.
- **Castle titles refresh themselves every seven days.** `castle_titles` holds the whole title (description, genres, season count, every season and episode name, poster/backdrop URLs), `castle_media` holds the pictures and `trailers` the clip, so the catalogue only needs a periodic pass to stay true. A `castle_sync` row (`last_sync_at`) records when the last pass finished; `startCastleSyncIfDue()` runs at boot (after `backfillSavedCastle`) and from an hourly `unref`'d timer, and starts a pass only when the timestamp is missing or older than 7 days. Offline mode returns before any fetch and leaves the timestamp untouched, so a week is retried once the switch is back on. A pass refetches the base row, then `fillAllSeasons(id, { refresh: true })` re-reads every season (new and renamed episodes land), then warms missing poster/backdrop/episode art and queues a trailer that is not `ready`. Merges only - `mergeTitle` keeps a saved value Castle omits - and nothing in these paths deletes a title, image or trailer; a failed title keeps its row for the next window.

- **A Castle cover is only used as the backdrop when it really is horizontal.** Castle points both `coverVerticalImage` and `coverHorizontalImage` at the same portrait file for some titles (The Boys: 375x562 twice), so the 16:9 card and the sheet hero cropped it to a band of legs. `castleArt()` in `server/castle.js` reads the frame size out of the saved bytes (`imageSize`, JPEG SOF / PNG IHDR; SQLite hands BLOBs back as `Uint8Array`, so normalise first) and keeps the saved backdrop only when it is wider than tall. Otherwise it resolves the IMDb id (`resolveImdbId`) and caches Cinemeta's `background` under `title:<castleId>:backdrop:wide`, falling back to Castle's own picture when the lookup fails (10 min negative cache, so a title with no Cinemeta match costs nothing after the first try). That route is `Cache-Control: no-cache` + ETag, and `castleArtUrl()` in `public/app.js` appends `?v=2` - a browser that cached the old portrait under the plain address would otherwise keep it for the week the old header promised.
- **Torrent progress is aria2's, not the file size.** BitTorrent writes pieces out of order, so `stat.size` hits 100 % while half the pieces are missing. `server/torrent.js` polls aria2's JSON-RPC (`tellActive`, then `tellStopped`) for the per-file `completedLength` and live `downloadSpeed`; a magnet has two GIDs (metadata, payload), so the entry is matched by its on-disk path. Phase mapping: download 0–0.8, verify 0.82, remux 0.84–0.96, subtitles 0.97, done 1.
- **A title shows its wordmark wherever its name would be, and every one comes from the catalogue.** `castleWordmark()` in `server/castle.js` resolves the IMDb id once and caches Cinemeta's transparent PNG in `castle_media` (`title:<id>:logo`), served at `/api/castle/art/:id/logo`; files on the drive keep `/api/art/:id/logo` through `officialArt()`. One helper, `applyHeroLogo()` in `public/app.js`, drives the three sheet heroes (`#modalLogo`, `#onlineLogo`, `#castleLogo`), and `buildCard()` draws the same image in `.card-logo` - the library route for a local file, `castleLogoUrl()` for a saved Castle snapshot. The text title stays in the DOM and comes back when the logo 404s (obscure titles have none), and "IN YOUR LIBRARY" is a `.lib-chip` in `#castleMeta`, never a kicker above the wordmark.
- **Loading states are shimmers in the shape of what is coming.** The catalogue paints 18 `skelPoster()` cards inside `#onlineGrid` (the `#onlineLoading` spinner is never shown), and a Shuffle with cards already on screen keeps them and only sets `aria-busy`.
- **Watchdogs hand a dead swarm to the next release.** `STALL_TIMEOUT_MS` 5 min with no verified byte, and a slow-swarm rule (under 120 KiB/s averaged over 3 min after a 3 min warm-up, only while >300 MiB remain) abort aria2 and try the next candidate. Ranking follows the container decision: with `copyVideo` (the client's own `decodesHevc()`) an HEVC release is stream-copied, so its AAC first track earns the +80 audio bonus, while an HEVC release from a client that cannot copy it takes −120 (a GPU transcode of the episode costs far more than the audio encode saves). 1080p/2160p +300 and anything lower is dropped before scoring (`ACCEPTED_QUALITY`, so a 720p release is never downloaded); a 1-2 seeder release stays as a last-resort fallback at -300 (0 seeders is dropped), below every healthy option; `min(700, seeders * 10)`; size bands (`sizeScore`: ≥8 GB −200, ≥4 GB −140, ≥2 GB −80, ≥1.2 GB −40, ≥700 MB 0, ≥300 MB +20, else −20); dual audio +120, English + other +80, English-only +40, original language +40, AAC audio +180 (a release that installs by rename, worth 18 seeders), pack −60, movie pack −250. Candidates are ordered single ≤3 GiB (≤6 GiB for a movie) → larger single → pack ≤limit → larger pack, and `planTorrentRelease()` returns null (Castle fallback) when no 1080p+ release survives. `GET /api/castle/plan` retries a failed episode once and marks the answer `partial` + `failedEpisodes`, which the sheet shows as "Torrentio unreachable - tap to retry" instead of disabling the episode as unavailable; `POST /api/castle/download` retries the Torrentio lookup once before falling back too. `POST /api/downloads/:id/retry` asks the ranking again (`job.refreshCandidates` in `runTorrentJob`) so a retry can pick a release the old candidate list never had. A slot in the queue is a **transfer**, not a whole job: `downloadMaxActive` (Settings, default 3) caps aria2c swarms, and `attemptRelease` hands its slot back the moment the file is on disk (`releaseSlot`), so the next queued episode starts downloading while this one is still verifying, remuxing or fetching subtitles - the remuxes themselves stay serialized by the media lane. `POST /api/downloads/:id/pause` stops one transfer and keeps its partial payload; `/resume` puts it back in the queue.
- **The download queue survives a crash or restart.** Jobs are saved to `<library root>\.cache\downloads.json` (atomic temp+rename, serialized, coalesced every 3 s, flushed on exit) and restored by `startRestoredDownloads()` after `initDownloads()`. Jobs that were downloading come back queued, unless offline mode is on, in which case they stay paused. aria2c resumes from its `.aria2` control file; an interrupted ffmpeg remux or HLS `.part` is deleted and rebuilt. A resumed release that cannot finish gets one clean attempt after wiping its temp folder before failover. On boot the app kills orphaned `aria2c`/`ffmpeg` whose parent is dead and whose command line points inside the library, then deletes every `.cache\torrent\<id>` folder no restored job owns (folders held by another live instance are spared). The last 40 finished/failed jobs stay as history; cancelled jobs are removed immediately. On restore, a completed job whose saved destination no longer exists adopts the single same-stem `.mp4` in that folder, so a renamed file (or one written by an older build that mislabelled the quality) and the Finished list cannot disagree.
- **The remux is decode-bound, so the decode runs on the GPU.** A 10-bit HEVC release spends most of its remux in the CPU decoder, not the encoder. On a 90 s 1080p Main10 clip this desktop (i5-10400F, RTX 3070) measured: CPU decode + `h264_nvenc p4 -cq 21` + AAC 5.1 re-encode 15.8 s, NVDEC + `p1 -cq 23` + AAC copied 5.7 s, VMAF 97.0 both ways (75.2 MB against 78.7 MB). `-hwaccel cuda` *without* `-hwaccel_output_format cuda` is a trap: every frame is downloaded back to system memory and the clip takes 9.9 s, slower than software decode at 8.4 s. Hardware frames are only valid for `h264_nvenc`/`h264_qsv` (`scale_cuda`/`scale_qsv` converts Main10 to 8-bit on the GPU); `h264_amf` and `libx264` keep the software path. The native AAC encoder is single-threaded and cost as much as the video once the video got fast, which is why an AAC track is copied instead of re-encoded. `VIDEO_COPY=1` goes further and copies the source video into the MP4 untouched (`-tag:v hvc1` for HEVC): 0.6 s for the same clip, playable only where the browser decodes HEVC in hardware, a black frame everywhere else, so it stays off by default.
- **A copied video leaves the audio encoder alone on the CPU, so the audio is split.** `copyVideo` (the client's own `decodesHevc()` from `public/common.js`) copies an HEVC stream instead of transcoding it; `VIDEO_COPY=1` forces the same for every non-h264 codec. With the video copied, the remux is one native-AAC thread: `-aac_coder fast` (25.3x realtime against 10.6x for the default `twoloop`, same AAC-LC, same size) and then `remuxToMp4` splits every re-encoded track into up to 6 pieces, encodes them at the same time and joins them with a stream copy before the final mux (26 min 5.1: 62.3 s in one pass, 17.9 s as six pieces, timeline unchanged). A video transcode keeps the single pass because NVENC is the ceiling there, and any parallel-audio failure falls back to it. `-movflags +faststart` is not used: it rewrites the whole output (33.0/28.0 s against 18.3/17.3 s for a 1 GB episode) and the range server plus Chromium's tail request do not need a front moov. Copying E-AC3/AC-3 into the MP4 is not an option (Chromium decodes neither) and Opus in MP4 encodes no faster than AAC `fast`, so the audio is always AAC. Measurements live in `benchmark/`.
- **A file the browser can play is never converted.** `pickTracks` returns `direct` when the client's own `canPlayType('video/x-matroska; codecs="avc1.640028, mp4a.40.2"')` probe says it opens Matroska, the video needs no transcode and the track it will play first is AAC; `attemptRelease` then renames the downloaded release into the library instead of writing an MP4 (0.0 s against 6.8-28.6 s, and the bytes are written once instead of twice), and the job skips the "remuxing" stage entirely. Brave plays Matroska served as `video/x-matroska`: a real HEVC Main10 + 2x AAC episode showed its first frame in 0.7-1.0 s and seeked to 15:00 in 1.2 s, the same as an MP4 copy of that content (1.01 s / 0.15 s) that cost 9.2 s to build. E-AC3/AC-3 as the *first* track disqualifies the file (the video plays, `webkitAudioDecodedByteCount` stays 0) and keeps the remux; mixed releases whose original track is already AAC still go direct. Subtitles are extracted once for all 29 tracks in 1.3-3.7 s. The dub variant is then the only remaining conversion. Numbers in `benchmark/mkv-direct.csv` and `benchmark/direct-install.csv`.
- **The library folder is a setting, not a build constant.** `POST /api/settings/library-root` validates (absolute path, existing folder, writable `.cache`) and writes `config.json` beside the app, because `settings.json` lives inside the library and would move with the folder it points at. The root is resolved once at boot (catalog DB, artwork cache, download queue), so the sheet offers "Restart now": `/api/restart` spawns the exe again with `NETFLIX_WAIT_PID`, and `bundle/entry.js` waits for that pid to exit before starting, so the new instance never finds the old server alive and quits again. The restart drops `NETFLIX_NO_BROWSER` so a tab comes back, and answers 409 under `npm start` (`canRestart: false`). Per-library settings (`offline`, `castleFallback`, `autoplaySound`) live in that library's `.cache\settings.json`, so a different folder starts with defaults.
- **Auto-play sound covers the trailers, never the player.** `autoplaySound` (on by default, Settings → Playback) is the mute default for `playPreview` on the billboard and for `playCastleTrailer` in the series/catalogue sheet; each trailer's speaker button still overrides it for that visit. The watch player ignores the setting: a show always opens with sound, and `attemptAutoplay()` only falls back to muted when the browser refuses an unmuted start, so an audio policy never leaves a black screen. Clicking the hero picture while the preview plays skips it (`skipPreview`); `heroPlay`/`heroInfo`/`heroMute` keep their handlers.
- **Skip Intro** windows come from `server/intro.js` in this order: `<name>.intro.json` sidecar → `.cache\intro.json` → ffprobe chapters → IntroDB (`https://api.introdb.app/intro?imdb_id=&season=&episode=`, keyless; the IMDb id is resolved once per series through Cinemeta). A film has no season, so it asks IntroDB's movie segments (`/segments?imdb_id=&is_movie=true`) and then TheIntroDB (`https://api.theintrodb.org/v2/media?imdb_id=`, keyless) instead; both report a null start for a window that opens the picture, which becomes 0, a `no_intro` flag means the community knows there is none, and a window that starts after 15 min is a mislabelled scene, not an intro, so it is dropped. Results are cached per episode (`<seriesKey>#s<n>e<n>`) or per film (`<file id>`). There is no guessed fallback: unknown timing means no button, so the cold open is never skipped. The button follows the playhead instead of a dismissal flag — seeking back into the window brings it back — and `#skipIntroFill` grows with the elapsed share of the window so the viewer sees how much intro is left.
- **Full-range HEVC is repaired by the app, never by hand.** A release can carry `color_range=pc` (samples spanning 0-1023 in 10-bit); every Chromium build ignores that flag for HEVC and decodes the samples as limited range, so blacks lift, highlights clip and hues drift. The same flag on H.264 is honoured, and the container (MP4 or Matroska) makes no difference - measured with two encodings of one frame: the H.264 and the limited-range HEVC painted correctly, the full-range HEVC and its Matroska remux did not. The library probe stores `colorRange` (`server/library.js`, plus the same field on `probeMedia`), `server/colorfix.js` queues every HEVC item whose range is `pc`, and one ffmpeg pass maps the samples with `scale=in_range=pc:out_range=tv`, re-encodes the video through NVENC (`hevc_nvenc p5 -cq 22` with NVDEC first, then CPU decode, `libx265 fast -crf 20` last), copies the audio, and swaps the result in only after ffprobe confirms HEVC + `tv` + the same duration. The candidates are tried on a real full-range HEVC sample kept in `.cache\colorfix-sample.mp4`, because `-hwaccel cuda` cannot attach to a lavfi test pattern. Two files encode at a time (`MAX_PARALLEL`), below normal priority. No new repair starts while something plays, except the title the viewer just opened: it jumps the queue, and since the swap is a rename the open player survives, that one may start and finish mid-playback; every other title waits for playback to end. A rename the player does block is retried later with the finished copy kept next to the file. State lives in `.cache\colorfix.json` (one automatic attempt per file, `POST /api/colorfix/:id` prioritises or retries, `GET /api/colorfix` reports jobs + queue), payloads written before the field existed are re-probed once, the Downloads drawer lists the repairs in a "Repairing colours" block above the download cards, and the player says why the file looks wrong, then reopens the same stream at the same second once the swap lands (the stream URL carries `?v=<mtime>`, so the browser cannot hand back the file it already opened). The freshness is not left to the folder scan: `refreshItem()` in `server/library.js` re-stats the file on every `/api/item/:id` and re-probes when size or mtime moved, and `public/watch.js` compares the item version every 10 s (and on tab focus) while a title is open, reopening at the same second whenever the bytes under it change - paused stays paused, playing keeps playing. Measured: 120 s slice repaired in 27 s (4.5x realtime), 1080p anime episode 80 MB against 92 MB, four 180 s 720p clips as two parallel pairs 99 s then 29 s, and a 180 s 720p clip opened and playing in Chromium, prioritized from the player page: repaired in 15 s (11.8x realtime) while the video kept playing, with the page switching to `?v=<new mtime>` at the same second and no reload (the paused variant held both its position and its pause state).

## Gotchas

- Windows paths: IDs are base64url of the path relative to the root.
- Pictures are generated on demand by `server/pictures.js`; the JPEG lives at `<cache>\pictures\<sha1(id)>-<width>.jpg` and its row in `catalog.db` keeps source size/mtime so a rebuild only happens when the video changes.
- Subtitles are plain sidecar `.vtt` files next to the video (`<name>.<lang>.vtt`); `syncSubtitleTracks` reads them into `catalog.db` once per directory-mtime change, and `/api/subtitle/:id/:lang` serves the stored body. Castle supplies most of them; OpenSubtitles legacy REST (`rest.opensubtitles.org/search/episode-<e>/imdbid-<id>/season-<s>/sublanguageid-<lang>`, `User-Agent` required, `.srt.gz`) fills the rest and the file is picked up on the next directory change.
- Legacy `pictures.db`, `library.db` and `trailers.db` are migrated once via `ATTACH` (only when the target table is empty) and then left on disk; `meta.json` is read only as a first-upgrade probe cache. Don't resurrect them as write targets.
- Hero rows must be returned normalized (`{image, video, startSec, builtAt}`); the raw SQLite row uses snake_case and breaks the preview route.
- `node:sqlite` is built into Node 22+; no dependency to install. `server/db.js` loads it with `createRequire(process.execPath)('node:sqlite')` — a top-level `await import` breaks CJS SEA bundling.
- The EXE is GUI-subsystem: there is no console. A notification-area icon (`bundle/tray.ps1`, started by `bundle/entry.js`, opt out with `NETFLIX_NO_TRAY=1`) offers Open, Online, Offline and Exit; it talks to the server over loopback and removes itself when the server stops answering. Quit also works through the profile menu (`POST /api/quit`, loopback only). A second launch probes `.cache\port` and only opens the browser.
- **The EXE carries the favicon, and the tray icon always sits outside the overflow.** `bundle/build.mjs` replaces icon group 1 of the PE with `public/favicon.ico` (`resedit`, dev dependency) right after the GUI-subsystem switch and before `postject` injects the blob, so Explorer, the taskbar and the tray all show the same picture. Windows has no API for "keep this icon visible": the switch is `IsPromoted=1` under `HKCU\Control Panel\NotifyIconSettings`, keyed by `ExecutablePath`. `bundle/tray.ps1` writes it just before the icon appears and re-checks it on the 3 s watchdog, re-adding the icon at most every 20 s when Explorer resets the value.
- postject prints `warning: The signature seems corrupted!` during injection — expected.
- npm 11 blocks install scripts by default; if `ffmpeg-static/ffmpeg.exe` is missing, run `npm install-scripts approve ffmpeg-static` or the package's `install.js`.
- Never commit `.cache/`, `node_modules/`, `dist/`, `.build/`, `bundle/manifest.json`, or downloaded media.
